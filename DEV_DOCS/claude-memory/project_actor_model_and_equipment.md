**Sponsors/“tie everything together” (2026-06-24, commit 8981425):** the legacy `sponsors` table is **empty/deprecated** — sponsors live on the **actor model** (`sponsorships.actor_id` → `actors`, + an `actor_roles.role='sponsor'` row). The dashboard Sponsors tab + Sponsorships tab + "Add sponsor" were repointed to actors (Add sponsor now inserts an `actors` row kind=org with a sponsor role). General rule when something "isn't tied together": the UI is probably still reading a legacy table (`sponsors`, possibly `clients`/`contractors`/`artists`) instead of `actors`/`event_participants`. Prefer actors. See [[project_event_hub_and_di2_money.md]].

**Actors management tab (migration 048, commit f798bdb, 2026-06-24):** new "Actors" nav module (Partners group) — one table for the whole `actors` registry. `actors.status` added ('active'|'on_hold'; archive = deleted_at). Features: inline-edit Name/Email/Phone/Instagram cells (contenteditable, save on blur/Enter via `saveActorField`), per-row Status select (active/on_hold/archived → `setActorStatus`), Kind select, role chips edited via toggle modal (`openActorRoles` → actor_roles), sortable columns, search + status filter, event counts. Code: `loadActors`/`renderActors`/`renderActorsTable` + `actorState`. Search re-renders only #actorsTable (keeps input focus). This is the master registry behind the Sponsors/Artists/Clients/Customers lenses. **Migration 049 (commit 11f4110):** `actors.org_id` (person→org affiliation; venues.actor_id already existed for org→venue) + widened `actor_roles.role` check to add photographer/videographer/producer/organizer/volunteer/partner/designer (staff already present). Actors tab now has: an "Org / members" column (person → inline org dropdown via `setActorOrg`; org rows show member count + a venue-assign modal `openOrgVenues` that sets venues.actor_id), a **multi-select role filter** (chips, contractor + all roles filterable), and a People/Orgs kind filter.

**Vendors revamped into own tab (migration 060, commit 3fb9812, 2026-06-26):** Vendors moved OUT of the Venues toggle into a top-level **Vendors** module (Partners, signed_off, operations/full) — `panel-vendors` + custom `loadVendors`/`vendorState`. New `actor_vendor_details` table (actor_id PK → category, account_ref, default_payment_method, typical_use; RLS = `user_can_access_module('vendors') OR is_master_admin()`). Categories (Software & Subscriptions / Equipment & Gear / Marketing & Ads / Travel / Talent & Contractors / Venue & Space / Supplies / Professional Development / Platform & Fees / Other) **auto-seeded from each vendor's dominant expense category**. Tab: clickable category-filter chips w/ counts + search + sortable; KPIs (count / total spend / categories); inline category select; per-row spend/txns/last/contacts/✉ + multi-select email; detail view = editable attributes + purchase history (expenses) + contacts (v_vendor_contacts). **Spend is computed from expenses(vendor_actor_id) so it auto-gates** — master sees totals, staff see $0 (expenses RLS 043/057). Venues tab is now venues-only (vendor toggle removed; venuesState.mode forced 'venues'; old renderVendorList/vendor-detail code left dead but unreachable). To recategorize: inline select or the detail. See [[project_staff_access_model]].

**IG-per-event + marketing spend (commit e4fa5a5):** event Overview "Engagement & marketing" section shows IG follower counts captured for the event (from `metric_snapshots` tagged `source='event:<id>'` — the back-dated Log-IG flow) + marketing spend (expenses where category ilike '%marketing%'). Files-tab vendor dropdown now lists only `actor_roles.role='vendor'` actors. Assign-equipment popup has an EQUIP_CATEGORIES filter.

**Equipment (2026-06-24):** `equipment_inventory` was reconciled to `Financial/ComeWith_Work_Expenses_Master.xlsx` → "Equipment (Capital)" sheet. Buckets = first letter of serial #: **D=DJ, S=Sound, C=Camera, M=Misc, W=Wire, A=Accessories** (6 buckets; stored in `equipment_inventory.category`). 13 existing rows UPDATED in place (preserve ids/event links — Osmo on DI#2, 7 items on Knicks watch party 529cc7a9), 56 master items inserted → ~68 rows. The 3 wrongly-"retired" (DJI Osmo C001, iPad, KRK Subwoofer S006) set back to available. Equipment tab now has category filter + an add/edit modal (rows clickable) showing per-item event usage history + archive (soft-delete). Venue detail shows full event history; edit-core modal now includes venue/doors/end/description.

**Legacy tables RETIRED (migration 047 applied to prod 2026-06-24, commit fcb44cd):** the legacy person/org tables are **DROPPED** — `clients`, `sponsors`, `artists`, `contractors`, `artist_bookings`, `artist_notes` no longer exist (all were 0 rows; actors is the single source). Also dropped: empty coupling columns (`*.client_id`, `sponsorships.sponsor_id`, `raffle_prizes.donor_sponsor_id`, `photos.artist_id`) and 4 orphaned legacy views/matviews (`v_sponsor_history`, `v_artist_history`, `mv_repeat_sponsors`, `mv_top_artists` — the `refresh-materialized-views` cron now refreshes only `mv_cross_event_kpis`). `inquiries`/`agreements`/`income`/`mileage` gained `actor_id uuid → actors`; the "Customers can read own agreements" RLS policy now keys on `actor_id`. Dashboard fully repointed (income/agreement pickers + caches + queries/renderers use actors role 'customer'; Sponsors/Sponsorships/Clients/Artists tabs + both sponsor pickers already on actors). **No reference to any legacy table remains in dashboard.html.** (`actor_source_links` still has 5 'contractor' provenance rows — harmless text refs to dropped ids.)
