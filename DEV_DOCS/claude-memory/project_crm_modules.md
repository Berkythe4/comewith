CRM trio rebuilt 2026-06-25 as custom loaders (commits f68e326 + audit fix e0543e5), same pattern as [[project_historical_events_backfill]] Income/Expenses/Artists. All three tables were **empty (0 rows)** at build time — UI built to work when populated, not yet verified against real data.

- **Inquiries** (`loadInquiries`/`inqDash`): lead pipeline from `public.inquiries`. Status pipeline aggregates (Open=new+contacted+quoted, Converted, Lost, Win rate=converted/(converted+lost)) computed over ALL rows (pipeline health, not the filtered set — deliberate, differs from Agreements). Search + status/source filters, inline status `<select data-inqset>`, row-click→detail modal, **"→ Client"** (`convertInquiry`) creates a customer actor + actor_role + sets inquiry.actor_id + status=converted, soft-delete (`deleted_at`). Public form on comewith.org is the inbound source.
- **Agreements** (`loadAgreements`/`agrDash`): contracts from `public.agreements`. Aggregates (Contracted=Σtotal_amount, Signed value=signed+completed, Awaiting sig, Drafts) over the FILTERED list. status/type filters, inline status, **Send/Resend** reuses the existing `data-send-agreement` global handler (→ send-agreement Edge Fn, needs actor.email), row→detail modal. "+ Add agreement" = FORM_DEFS.agreement (table=agreements, select-clients dropdown, status defaults draft). agreements also has `inquiry_id` (not surfaced — possible future inquiry→agreement link).
- **Clients** (`loadClients`/`clientDash`): roster = union of customer-role actors + any actor referenced by an inquiry or agreement. Per-client inquiry/agreement counts, contracted (Σagreement total), paid (Σincome.amount by payer actor_id), last activity; sortable columns; "+ Add client" (`openAddClient`, #addClientBtn) creates a customer actor. Edit contact happens in the Actors tab (not here).

**Agreements↔events + auto-file (2026-06-25, migration 054, commit 712ae53):** `agreements.event_id` (FK events) added; Add-agreement form has an Event picker (new `select-events` field type + `loadCachedEvents`), Agreements tab has an inline Event column + shows the linked event in the detail modal. When an agreement is set to **signed/completed** (or linked to an event while already signed), the new Edge Function **`file-agreement`** generates a self-contained **HTML snapshot** (parties/financials/signature/timestamps), uploads to the private `agreements` bucket at `event-agreement/<id>.html`, and upserts a `files` row (`subject_type='event'`, `subject_id=event_id`, `kind='contract'`) → surfaces in that event's **Files → Contract** bucket. Idempotent (deterministic path, reuse files row). Auth = service-role (internal) OR admin JWT (UI). `mark-signed` now calls it after a client signs (non-fatal) + **fixed a latent bug**: it still embedded `client:clients(...)` (dropped in 047) → repointed to `actor:actors(...)`. NOTE: the function's `SUPABASE_SERVICE_ROLE_KEY` env on prod is the **new `sb_secret_…` key**, not the legacy `eyJ` JWT — so internal `Bearer ${SERVICE_ROLE}` calls match by construction; raw **storage REST** calls still need the legacy `eyJ` service_role JWT (sb_secret gives "Invalid Compact JWS"). Bucket `agreements` allowed_mime_types extended PDF→PDF+text/html. **Two contract tables stay separate by decision:** `agreements` = client-facing deals (you selling), `contracts` (event hub, has event_id+document_id) = event counterparties (vendors/venues/artists). Verified E2E on prod, test data cleaned.

Status/type values match prod CHECK constraints exactly: inquiries.status ∈ new/contacted/quoted/converted/lost/archived; agreements.status ∈ draft/sent/signed/cancelled/completed; agreements.agreement_type ∈ events/rental. **NOT marked signed_off in module_registry** (Keith reviewing). RLS untouched (pre-existing admin is_admin() + customer-portal own-agreement policies). Audit bug fixed: clicking the inline status select used to also fire the row-click → opened the detail modal; guarded with `!closest('select, button, option')`.
