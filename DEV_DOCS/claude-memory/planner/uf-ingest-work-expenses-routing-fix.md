2026-07-07: fixed why the Jennifer finance dashboard showed ~$0 Come With actual for June 2026. Root cause in `scripts/uf_ingest.py` routing: `Work Expenses` was deliberately UNMAPPED and CW spend posted ONLY via exact (date+amount) match against the validated CW ledger xlsx (`ComeWith_Budget_Actuals_Model.xlsx`) — but that ledger stops at 2026-06-02, so every June/July Work-Expenses charge fell to `uf_review_queue` and never posted. Compounding: earlier `personal_xlsx` migration rows tagged Work Expenses were posted with `envelope=NULL`.

**Why:** Keith tags business charges "Work Expenses" in Simplifi; that tag IS the Come With signal. The ledger-only design was brittle (needs manual upkeep).

**How to apply:** (1) `rules/personal_envelope_map.yml` now maps `"Work Expenses": "Come With"`. (2) `uf_ingest.route()` step 3 (CW watchlist hit) now returns confident `("Personal","Come With",True,...)` instead of dumping to review — user chose "trust the tag + watchlist". So precedence: rules → CW-ledger match → watchlist → category-map(incl Work Expenses) → unmapped. (3) Backfilled Apr–Jul 2026 via `scripts/_remediate_cw_backfill.py` (drives off CSV candidate set, entity='Personal' only; UPDATE null-envelope rows, INSERT review-only rows, mark 23 review rows RESOLVED). (4) `scripts/uf_dashboard_build.py` review-queue query now filters `status='REVIEW'`. Backup: `data.db.bak_before_cw_remediation_20260707`.

Result — Personal budget "Come With" line actual: Apr −1826.90, May −567.80, **Jun −3933.10** (was −32.58), Jul −551.43. Idempotent: re-importing the processed CSVs inserts 0 rows.

**Come With TAB fix (part 2, same day):** the Come With tab = the CW business P&L, reads `entity='Come With'` (grouped by engine from the `note` last-`|` token; migration put ~100% under 'Indirect'). It was fed ONLY by the CW ledger xlsx (stops 2026-06-02), so the tab still showed ~$0 June after part 1. Fix: (a) backfilled `entity='Come With'` Indirect-cost mirror rows for Apr–Jul CW candidates NOT already in the CW ledger (`scripts/_remediate_cw_ledger_backfill.py`, source='simplifi_cw_mirror', note="Indirect / Overhead | Indirect", envelope Software/Venue/Other via `cw_bucket`); (b) `uf_ingest` now DUAL-POSTS: any charge routed to Personal/'Come With' with reason≠'cw_ledger_match' also inserts a `simplifi_cw_mirror` Come-With Indirect row. So both tabs stay synced. Now CW P&L actual == Personal CW line for these months (Apr −1826.90 … Jun −3933.10 … Jul −551.43). NOT a double-count: same charge = Personal cash outflow + CW business expense (two separate books, firewall design); the runway/`uf_model` is BUDGET-driven so actuals don't distort it. GOTCHA: `ingest_file()` calls `c.commit()` internally — a caller-side `c.rollback()` after it is a no-op (a unit-test row got committed and had to be deleted).

Cause: `uf_dashboard_build.py` hardcoded CW member (line) actual = `None`, computing actual only at the ENGINE level. **Audit-tab HTTP routing bug (2026-07-08, FIXED):** the Finance "Audit" tab did nothing because ALL `/api/audit/*` routes are defined INSIDE `_handle_finance_get` / `_handle_finance_post` / the do_PUT finance block, but `do_GET`/`do_POST`/`do_PUT` only forwarded paths starting with `/api/finance/` to those handlers — so every `/api/audit/*` request 404'd (summary, queue, run, confirm, dismiss). The Stage-11 unit tests passed because they call `finance_api` functions directly, bypassing HTTP. Fix: 3 dispatch guards in `src/web_server.py` now read `if path.startswith("/api/finance/") or path.startswith("/api/audit/"):`. Verified on a throwaway server: GET summary/queue → 200, POST /api/audit/run → classifies 6669 legacy `finance_transactions`, queues 6363 low-confidence (then restored to pre-test state — did NOT leave the 6363 items). NOTE two SEPARATE finance systems: legacy `finance_transactions`+`transaction_audit_queue` (the Audit tab, stale ≤2026-05-22) vs the uf model `uf_transactions`+`uf_review_queue` (Personal/Come With tabs, where "Amazon Prime" sits). They don't talk to each other. The drill-down popup "no charges" was just the un-restarted server (endpoint 404 → empty); fresh server returns charges fine.
