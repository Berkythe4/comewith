Come With NYC Radio

Making the episode video

Three files into a folder, one double-click, about fifteen minutes. This is what happens in between, every point where it stops you rather than shipping something wrong, and how to hand the whole thing to someone else.

The run

The one thing people get wrong

Type the number the audience knows

Episode 3 is show 7. The Elements run took shows 3 through 6, so the two counters have been apart ever since. The tool converts one to the other itself — you only ever type the episode number.

Typing 7 gets you Elements Ep 4, with Elements' credits burned into the slides.

Sharing it — another laptop, or another person

1 · Build the packet

on the laptop that has the credentials

# the tool, plus everything Ep 3 needs
python Radio/render/package_tool.py --episode 3

Makes CWR_render_tool.zip, about 12 MB. Send the mix separately — it's far too big to bundle.

2 · They install two things

once, then never again

  • Python 3 — tick Add python.exe to PATH on the first installer screen. That checkbox is the whole difference between this working and not.
  • pip install pillow
  • ffmpeg — winget install Gyan.FFmpeg, or brew install ffmpeg

3 · They run the same .bat

no login, no account, no password

Everything works — including rebuilding the tracklist if they edit the txt. The folder carries a read-only token for that one episode, so the tool pulls live data on its own.

The one thing it won't do from there is change the running order on the website.

Why they don't get a login — and don't need one

Martin and Henry are already master_admin on the dashboard, so this isn't about trust. It's that the render tool used to want a Supabase management token, which is a different thing entirely: it runs arbitrary SQL on production and deploys or deletes the site's functions. Only berky owns the project; handing that out to make a video would be wildly out of proportion.

So the tool doesn't use it any more. It reads one episode through the same public endpoint the website itself uses, keyed by that episode's share token. Scoped to one episode, and read-only — asking it to write the running order from a token is refused outright.

Changing what the video says

The wording

Radio\render\templates.json

Every word the video draws is in that one file — the opening slide, the closing slide, the strip along the bottom of each card, and the static upload tags.

Edit it, save it, run the tool. Nothing to rebuild, no code to touch. A typo can't break a render: it warns and falls back.

Symbols

one font, no emoji fallback

These work. These come out as empty boxes:

Render one card and look, before trusting a new symbol.

The cover

any image in the episode folder

Make it square. The renderer centre-crops, so a portrait cover loses its top and bottom on every card.

You get a warning before rendering if it isn't square, isn't RGB, or is too small to hold up.

By hand

# check the tracklist matches, then write the cues
python Radio/render/tracklist_from_txt.py --episode 3
python Radio/render/tracklist_from_txt.py --episode 3 --out-cues
python Radio/render/tracklist_from_txt.py --episode 3 --write-order   # updates the site

# render, verify, tag
python Radio/render/make_episode.py   --episode 3 --next-date 2026-09-10
python Radio/render/verify_episode.py --episode 3
python Radio/render/make_tags.py     --episode 3

# design only — the cards plus a one-second preview
python Radio/render/make_episode.py   --episode 3 --dry

The typed tracklist is the source of truth

Your .txt is the only place two things exist: the order the set was actually played in, and where each track starts. The site has everything else — links, artwork, genres, each artist's next New York show — so never retype any of that.

The dashboard's tracklist is what was planned. Nothing corrects it to what was played unless someone says yes at step 7.
