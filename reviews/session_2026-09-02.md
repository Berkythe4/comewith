## The arc

The session started as "add the DJ to the radio tasks" and ended with the venue
dimension moved into the database and a new class of data source. Almost none of
that was planned; each piece came from checking a claim before acting on it.

**The pattern that repeated, five times, in five different disguises: a zero that
was not a measurement.**

- The buzz score read DICE and Ticketmaster's missing RSVP counts as `0`. They
  publish none — RA publishes all 941. Galantis, whose shows are sold on DICE,
  scored 47 on the strength of a fact about a ticketing vendor.
- 191 SoundCloud scans had **failed**, and the dashboard was not selecting `ok`,
  so a failure was indistinguishable from an artist with no music.
- An artist with no uploads had their top-track plays scored as `0`. That one
  nearly shipped: it put **Ben UFO at 56** — 109k followers, 2,010 RSVPs — because
  the plays of a catalogue that does not exist are *undefined*, not zero, and
  catalogue size already recorded the same fact once.
- "Only one artist at Refuge" was three separate defects stacked, and the first
  was that `'Refuge'`, `'REFUGE'` and `'REFUGE '` are three strings holding 23, 1
  and 1 artists, two of which render identically in a dropdown.
- Lane 8 is missing from a tool whose three sources are all the same *kind* of
  source, so an empty result read as "not playing" rather than "cannot be seen".

**The decisions worth keeping** are mostly about authority rather than logic. Fuzzy
venue matching **suggests and never applies**, because no threshold separates
`randalls island` (same room, 0.97) from `green room 42` (different room, 0.87).
Bandsintown's electronic-only guarantee is **who we ask about**, not a filter on
what comes back, because Bandsintown returns no genre and any rule would have been
invented — which is also why Charli XCX cannot arrive. And the radio DJ resolves
FK-first while the public credit resolves name-first: the same two columns, opposite
precedence, because the question differs.

## Verification, given almost nothing could be clicked

No dashboard login and no JS runtime on this machine. Every migration was dry-run
against real prod and, where it mattered, **proved its effects inside the
transaction before commit** — 208's dry run created a venue from a real unmatched

## One honest note

**Migration 209 was incomplete and I applied it anyway.** It added
`link_items.emphasis` and set it on prod without adding the column to
`v_public_link_items` — the only thing `links.html` reads. The flag was set and
invisible, and nothing errored. Caught minutes later and fixed in 210 as its own
migration rather than by rewriting an applied file. The same review then found
that `saveLinks()` would have silently reset every promotion on the first Save,
because its upsert enumerates columns. A new column is one change per layer that
enumerates columns, and I had checked one of four. §64.
