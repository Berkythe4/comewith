## The arc

The ask was small and clear: a Linktree-style page, fully customisable without
having to come back to Claude. Two things about it were genuinely underdetermined,
so they were asked rather than guessed — **how many pages** (one, or several
addressed by slug) and **how much theming control**. Keith took several pages and
full custom with presets on top. Both answers changed the schema, so asking was
cheaper than rebuilding.

The rest of the work was mostly deciding what *not* to build twice.

**The editor wanted a live preview, and the obvious build is the wrong one.** A
small renderer inside `dashboard.html` that draws approximately what `links.html`
draws would have worked on day one and drifted by the second change. The planner
already carries exactly that duplicate on purpose (`v_plan_monthly` vs
`planModelMonth`) and pays for it with a permanent "change both" rule — worth it
there, where SQL and the browser cannot share a runtime. Here they can: the preview
is `links.html?preview=1` in an iframe, fed unsaved state over `postMessage`. One
renderer, and the preview cannot lie about the page because it is the page. It also
filters inactive and out-of-window rows before posting, since that is what the
public view does and a preview that shows more than a visitor sees is worse than
none. §59.

**Clicks were already free, but only if the identity is right.** The site's beacon
counts every link click. Attributing those to a link by URL would have been a guess
— the beacon stores a resolved absolute URL, a row may hold a relative path, and an
edited URL would silently inherit the previous one's history. Each rendered link is
stamped `data-track="link:<uuid>"` instead, and `v_link_click_stats` matches on that.

## What went wrong, and it was not the feature

`scripts/check_anon_exposure.py` finished a full run with **"Nothing is exposed that
should not be"** and never touched a single one of the five new objects. Its own
comment says "everything else discovered from the schema is checked too". There is
no schema query in the file — it walks two hand-written lists and stops.

This is §51 again, one file over: a check read as covering something its code never
touched. §51 was the financial views missing from a script; this is a comment
asserting behaviour the code directly beneath it does not have, which is worse,
because a wrong comment is a claim that nobody re-derives. Comment corrected in
capitals, the 207 objects named in both lists, and CLAUDE.md now requires every new
table or view to join one of those lists in the same commit. §58.
