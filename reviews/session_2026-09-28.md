# Session review — 2026-09-28 (finance ingest: settle before add) · DESKTOP

## The arc

Started as "the import updated Jennifer but not the Come With dashboard." That
was true and simple: the import had **never** pushed. Both halves of the push
existed and neither had a caller — `uf_export_cw.py` wrote a JSON file to disk,
`uf_push.py` sent one, and nothing joined them. 45 rows / $1,746.93 of August and
September spend had been sitting on Keith's machine for a month.

Wiring that up took an hour. The rest of the session was the five layers of wrong
underneath it, each found by the previous fix ceasing to hide it.

1. **The transport's payload whitelist was a placeholder** that dropped
   `external_ref` — the key the server dedups on. Had the push ever run, it would
   have duplicated the whole ledger instead of updating it. The two halves had
   drifted with nothing watching the contract.
2. **The cash reserve read $2,498 against a real bank balance of $2,956.** The
   importers post money *out* automatically and money *in* not at all;
   `revenue_in` was literally `0`.
3. **Bluevine swallowed every credit** — one branch, justified for the opening
   $5,000 of owner capital, silently ate a $357.39 Stripe payout.
4. **My own fix for (3) was wrong.** The Stripe payout was the NET of a $361.00
   fee already on the books. Recording it as income made the *cash* number right
   while double-counting the *revenue*. Caught by chasing a $0.79 residual.
5. **The 66-duplicate problem was never actually solved.** Adopt matched on exact
   date + exact amount, so it caught only the cleanest collisions. Measured: 26 of
   62 unreffed rows pair to a feed row at a **constant 1.0664 ratio** — $905.71
   double-counted, spanning 2024-12 to 2026-03.

- **Cash reserve ties to the bank statement exactly: $2,956.30**, from a five-part

## Decisions

- **§69 — a payment is not a fact about a day and an amount**; it is an event that
  discharges an obligation, and the obligation has its own date. Hence the
  hierarchy, and hence settlement never overwriting `date`.
- **Refusing to choose is a feature.** A guess lands in the P&L and is only
  findable by noticing a total look wrong. 27 queued items on the first run is the
  system working.
- **§70 — a version-keyed ledger silently overwrites.** 207 was used twice and
  `applied_migrations` replaced a row with no error.

## Mistakes worth keeping

- **I got the Stripe payout wrong** and shipped it before catching it. The tell was
  there at the time — Keith had marked the $361 income `received` an hour before
  my push — and I did not chase it until a $0.79 residual forced me to. An exact
  arithmetic tie is not proof of a correct model; it only proves the cash side.
- **I used migration 207 against a 22-commit-stale master.** `ls | tail` showed 206
  and I believed it. MERGE_ROUTINE step 0 exists for precisely this and I skipped
  it. The repair was bookkeeping only, but it silently falsified a record.
- **My first backlog scan was directional** (payment after cost) and missed the
  Janelle pair, where the hand-entered row was three days *later*. Found only
  because Keith asked an unrelated question about Marketing.
