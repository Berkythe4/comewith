# Session 2026-09-10 — Ep 4 tracklist, and the show we could not see

Ran on the **laptop** (`C:\Users\keith\comewith`). Prod migration 211 applied,
`pull-dice` deployed v22, prod data touched deliberately.

## The arc

Set out to do a small thing: turn a screenshot of Keith's Rekordbox playlist into
a tracklist he could type timestamps into, and correct SHOW 8 in the dashboard
because he had arranged the set outside the SoundCloud playlist and could not
sync it back.

Ended up fixing why a Lane 8 show at Brooklyn Storehouse — 4 of the 21 tracks on
this very episode — was invisible to the tool.

The route there went through three wrong answers of mine, each caught by Keith
asking one more question:

1. **"The event has no genre tag."** It does — `music:dj`, one of the fifteen we
   already query. My probe only looked at keys named `tags`/`genres`/
   `categories`; DICE puts it in `tags_types`. Keith's follow-up ("should we scan
   the no-genre shows and classify them?") is what forced the re-check, and the
   real cause turned out to be pagination. Had he taken the first answer we would
   have built a genre classifier to work around a missing `cursor` parameter.
2. **Clearing Kim Anh's show chip.** The chip was stale (Sep 6, already passed) so
   I cleared it and reported "no upcoming NYC date for anyone credited". She had
   four. Keith pushed back because he remembered pulling that artist from the tool
   himself. Root cause: I read `ra_artists.next_event_date` — one denormalised
   field — instead of `ra_events.lineup`. §62 warns about exactly this one field
   along, and I walked into it anyway.
3. **"Use the DICE artist-name search as the Bandsintown replacement."** Sound at
   the time; obsolete an hour later, because paging made every watchlisted
   artist's DICE event reachable by tag. Recommended and then withdrawn.

## Shipped

- **Ep 4 / SHOW 8** — rebuilt from the real Rekordbox export. 21 tracks in play
  order, BPM/key across, 21 of 21 show chips valid, 52 unplayed songs logged
  `passed@8` and carried to SHOW 9. Files in `Radio/Episode 4/`.
- **`pull-dice` v22** — follows `next_page_cursor`. 343 → 829 events for six extra
  HTTP calls. `maxDetail` default 240 → 600 in the same change, plus a 110s
  deadline, per-call timeouts, and `status: OK|PARTIAL`.
- **Migration 211** — a trigger filling an empty `ra_events.lineup` from the title,
  confirming only names we already track. 12 hits, all correct.
- **Two new tools** — `Radio/render/apply_station_from_rekordbox.py` (the SQL path
  for a set arranged outside SoundCloud) and `rekordbox_clean.py`, which the two
  existing export parsers now share instead of diverging.

## Decisions

- **Bandsintown is dead**, not pending. Their API is per-artist to that artist, so
  no key exists that lets us ask about a watchlist we do not own. `pull-bandsintown`
  stays deployed and permanently inert; `BANDSINTOWN_APP_ID` will never be set.
- **Confirm a name, never derive one** (§67). Parsing artists out of titles was
  measured and rejected; matching the full 3,349-name pool was measured and
  rejected. Only the watchlist / partners / played artists are confirmed.
- **The lineup fix is a trigger, not a puller change** — 2 of 12 hits are RA, so a
  puller version would have been three copies of one rule.
- **§65 is partly superseded.** Its rule about source KINDS stands; its measurement
  ("DICE contributed nobody") was an artifact of the pagination bug.
