# Session review — 2026-09-30 (campaign stats, DICE, guest DJ link) · DESKTOP

## The arc

Keith was preparing to teach the first guest DJ to build a radio episode, and asked
a string of "why does this number look wrong?" questions along the way. Every one was
a real bug, and most were a system reporting success over a failure.

1. **"82 sent shows as 164; 8/13 says 11 delivered."** Resend's `email.sent` echo made a
   second `sent` row; the duplicate broke the attribution lookup, orphaning 267 events.
   The 8/13 campaign actually reached all 87 (57 opened). §71.
2. **"1,041 events, none DICE — but 130 DICE artists?"** DICE had started answering 403,
   and the puller read that as "no shows", deleted the window, and reported OK. Artists
   survived only because the puller never deletes those. §72.
3. **"Find a new way into DICE."** A version header found in their JS bundle fixed it
   from a desktop, not from the edge runtime. The database (pg_net) gets through, so
   the calls go there. First test deadlocked pg_net by triggering the function through
   pg_net itself. §73.
4. **"Vintage Culture and Purple Disco Machine do have SoundCloud."** They did; every
   Refresh erased the match. Same bug in all three pullers. §74.
5. **"50 Cent and Armin aren't at the top by followers."** The sort read RA's count. §75.
6. **Then the build Keith asked for:** the guest link brought to parity (sorts, Buzz, row
   layout), and export to the DJ's own SoundCloud — then the same for every teammate
   from the dashboard. §76.

## Key decisions

- Ignore Resend's `email.sent`; count Sent by unique recipient.
- A delete-then-insert puller proves the source answered before it deletes.
- DICE's HTTP goes through the database; never invoke `pull-dice` via pg_net.
- Pullers omit columns they have no value for; RA carries enrichment across.
- Buzz lives once, in `assets/buzz.js`.
- Exports to a person's own account are one-shot OAuth; no token is ever stored.
- The dashboard's row layout is the standard for external links.
