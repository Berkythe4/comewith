# Session 2026-10-17 — multi-artist content tags (DESKTOP)

- **Set out to:** let Keith tag several artists on content in an event's Content tab.
- **Found:** only recap links and library assets could name an artist, and only one
  each; posts and photos could not. `v_artist_content` never checked `is_public`, so
  tagging a staged track would have put it on the artist's public page. The event edit
  modal rebuilt recap items with one artist and would have dropped any extra tags.
- **Shipped:** migration 221 (`artist_ids` everywhere; the view expands both keys and
  gates staged items). Chips, "+ artist" and tag-on-all in the event hub. Then, at
  Keith's ask, the Content Center: Posts-table column with a bulk tag, Pipeline tags,
  and Artists boxes in the post composer and in Add content.
- **Decisions:** arrays, not a join table (recap items have no id); `artist_id` stays
  mirrored to `[0]`; a form draws the Artists box only when it could read the tags
  (§94).
- **Aside:** VeeDay 7/11's SoundCloud oembed 404'd for about a minute after upload, then
  worked (§95). Made 320k MP3s of the KRNeY and VeeDay 7/11 sets.
- **Parked:** a Content Center artist filter; tagged photos/clips on artist pages.
